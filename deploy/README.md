# Скрипты развёртывания Docker

Текущий способ развёртывания использует Compose-файлы в корне репозитория и скрипты в этом каталоге. Полная инструкция по настройке, резервному копированию и восстановлению, переходу с systemd и правилам AWS приведена в [основном README](../README.md) и [инструкции по сетевым правилам AWS](AWS_FIREWALL.md).

## Быстрый запуск

На каждом сервере с Ubuntu 22.04 или 24.04 клонируйте репозиторий и сначала подготовьте настройки:

```bash
# Сервер Listener
cp .env.listener.example .env
nano .env
sudo bash deploy/install.sh

# Торговый сервер
cp .env.trader.example .env
nano .env
cp config/api_keys.example.json config/api_keys.json
nano config/api_keys.json
sudo bash deploy/install.sh
```

При запросе выберите роль текущего сервера. Установщик сохраняет существующие настройки, требует `TRADE_DRY_RUN=true` для запуска торгового узла и не останавливает и не отключает systemd-службы. При запланированном переходе вручную остановите и отключите старые службы до запуска Docker, особенно Listener, использующий те же Telegram-сессии.

## Скрипты

| Скрипт | Назначение |
|---|---|
| `install.sh` | Устанавливает Docker Engine и Compose Plugin из репозитория Docker для Ubuntu, собирает выбранный узел, проверяет настройки и запускает его. |
| `check-config.sh <роль>` | Проверяет обязательные параметры приложения, не меняя сервер. |
| `start.sh <роль>` / `stop.sh <роль>` | Запускает или останавливает контейнеры, не удаляя тома данных. |
| `restart.sh <роль>` | Перезапускает службы выбранного узла. |
| `update.sh <роль>` | Получает обновления Git без слияния веток, пересобирает образы и пересоздаёт контейнеры; тома данных и сессии сохраняются. |
| `logs.sh <роль> [служба]` | Показывает журналы Docker Compose. |
| `status.sh <роль>` | Показывает состояние контейнеров и проверяет локальный Redis. |
| `backup.sh <роль>` | Сохраняет настройки, сессии и журналы (если применимо), а также снимок Redis RDB. Listener ненадолго приостанавливается для целостного копирования SQLite. |
| `AWS_FIREWALL.md` | Содержит необходимые ограниченные правила AWS Security Groups. |

Если роль не указана, скрипты читают её из `.node-role`. Выполняйте команды через `sudo bash ...`, если пользователь ещё не получил доступ к сокету Docker. Контейнеры приложения запускаются с UID/GID этого пользователя.

Файлы `*.service` и `deploy/.env*.example` сохранены для существующих установок на systemd; установщик Docker их не устанавливает и не изменяет. Перед переходом следуйте инструкции по миграции из основного README.
